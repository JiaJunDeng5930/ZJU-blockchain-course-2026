# Transaction receipt reconciliation

An approval, swap, liquidity operation or faucet request already creates one journal entry before sending its transaction. Wallets may replace that transaction with the same sender and nonce. Receipt observation now reconciles that existing entry; there are no new signing controls or transaction submission paths.

`ReplacementSearch.v` defines a public descriptor, replacement classification and bounded read-only receipt lookup. A descriptor contains hash, sender, nonce, destination (including `null` for contract creation), input bytes, value and observation block. The same-call relation compares sender, nonce, destination, input and value. Its proved field projections connect the classifier to those quantities. Hash, expected sender, nonce and receipt fields are checked again when `Transactions.observe_replacement` updates the entry. A different call produces `Superseded` (public state `replaced`), even if its actual receipt succeeded. It cannot authorize the next swap after an approval.

`Transactions.replaced_entry_never_confirms_original` proves that every entry event preserves this classification. `TransactionHistory.restored_replaced_remains_replaced` connects the invariant to restored entries. Restoring a replaced entry clears its unverified receipt quantities, preserves the replacement fact and public lineage, and grants no operation authority. A later successful receipt for the replacement therefore cannot become success for the original business request. Existing confirmed entries remain final against late observation errors.

The interpreter first reads the known transaction and receipt using viem. Already mined transactions take this direct receipt path. If the receipt is missing, the extracted model selects the observation strategy. A live transaction without usable metadata uses viem's existing replacement-aware receipt waiter. Historical entries without nonce metadata remain explicitly unresolved when their old hash is unavailable; they are never resent or inferred successful from account nonce growth.

For a saved descriptor, the model reads nonce at one fixed head. A pending slot waits for a strictly newer block through viem's block subscription. A consumed slot reads the genesis nonce, then locates the first consumption block by bounded binary search and fetches that one block's transactions. The model chooses each midpoint, requested address and height, bound update and candidate. Lemmas prove strict midpoint progress, bracket preservation, decreasing fuel, stale-height rejection and candidate sender/nonce membership. The monotone-oracle theorem is conditional on the external nonce observations; it is not an implementation or proof of EVM nonce semantics. The private interpreter accepts an existing journal entry identifier, not an arbitrary address/nonce query.

Receipt lookup has one extracted 180-second deadline. Completion, error and timeout release its block subscription. An in-flight replacement receipt arriving after timeout cannot publish replacement success. Fixed-head queries are not restarted by newer heads. Read failures leave the existing submitted/replaced meaning with a visible error and the existing refresh action can recheck it. No observation re-signs or resumes a restored operation.

History archive version 2 adds `descriptor` and `replacements` to the existing entries. `originalHash` is derived from the first lineage edge, or from the current known hash when there is no edge. The decoder accepts exactly versions 1 and 2. Version 1 becomes a missing descriptor and empty lineage; it does not fabricate a nonce. The archive contains public transaction facts, never keys, signatures or continuations. Foreign page archives remain read-only and cannot mutate the current page's transactions or request a save, as proved by `foreign_descriptor_is_read_only` and `foreign_replacement_is_read_only`.

The trusted boundary includes solc, Rocq extraction, OCaml/js_of_ocaml compilation, the JSON codecs, viem, wallet interfaces and RPC observations from a coherent canonical chain. Same-call replacement means equality of the recorded call request; it does not assert equivalence of all EVM transaction fields or execution contexts. The existing actual-receipt and contract assurance boundaries still apply. Viem represents account nonces as JavaScript numbers, so descriptors above its exact integer range are refused rather than rounded. This repair does not add chain reorganization handling or prove the external interfaces.

Run `npm run test:replacements` for the independent public-entry acceptance runner. It uses isolated real chains, wallet requests, manual mining, WebStorage archives and separate producer/consumer processes. Its scenarios cover live same-nonce repricing and cancellation, approval continuation, past-block recovery after process exit, legacy archives without metadata, previously replaced records after restoration, faucet sender/beneficiary separation and contract creation. It does not inspect the extracted implementation to derive its success criteria.
